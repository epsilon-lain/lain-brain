# Apertus API ZIP revision diagnostic

Zero-training API replay of five predeclared v24 episodes: the real 435 wrong saved note, the 49 counterexample, the correct 315 note, an equal-sign check, and a different-input check. The model supplies its own sign/factor classifications, KEEP/RETRACT action, collected replacement expression, and reflection. Written responses are committed before grading; saved notes are reloaded before follow-up queries under no-note, old-note and new-note conditions. The original v24 prompts and exact polynomial auditors are embedded without changes.

Run `runpy.run_path(path, run_name="zip_api_runtime")["run"](globals())` in the Notebook with the existing API configuration. Recognized variables include APERTUS_API_KEY / TEACHER_API_KEY / OPENAI_API_KEY / API_KEY, APERTUS_BASE_URL / TEACHER_BASE_URL / OPENAI_BASE_URL / BASE_URL, and APERTUS_API_MODEL / APERTUS_MODEL / TEACHER_MODEL / OPENAI_MODEL / API_MODEL. Existing configured client.base_url and client.api_key can also be reused. Otherwise set ZIP_API_CONFIG with api_key (a reference to your existing private variable), base_url and the provider's model ID. Do not commit keys. The endpoint must expose OpenAI-compatible /chat/completions. Without a model ID, GET /models selects an available Apertus v1.5 8B ahead of 70B. No provider URL is guessed.

Optional ZIP_API_CONFIG settings: token_field = max_tokens or max_completion_tokens; max_tokens = 256..2048 (default 1024); extra_body can contain explicit provider thinking options chat_template_kwargs, reasoning_effort or enable_thinking. Provider defaults govern sampling when no options are specified. The test changes the output interface from constrained local scoring to free text; no comparative action-probability claims are made.

The default output is /mnt/workspace/lain-zip-pilot/zip-apertus-api-<binding>. Rerunning identical code/configuration reuses sealed committed responses. At most 72 attempted POSTs across resumes; pending requests may have reached the provider and may be charged even without a saved response. Resume records the uncertainty instead of claiming exactly-once API execution. HTTP failures are not retried automatically. Partial and complete review ZIPs contain untouched outputs, prompt bodies, audits, and versioned notes; credentials and model weights are excluded. API revisions are not pinned by tensor hashes; requested/returned model names and provider fingerprints are recorded.

Interpretation: both wrong notes are inherited/designed, not authored by the API model. A separate cold answer is genuinely generated before showing the inherited wrong note. A successful inherited revision chain is evidence for conditional memory repair, not proof that the API model discovered its own unnoticed error. Candidate closed loops require correct same-input sign calculations, actual model withdrawal, an independently verified student replacement, and two correct later applications. Reflection semantics must still be read by a human. Equal signs are not proof of equality. KEEP on an inconclusive check means no withdrawal from that evidence, not certification of the false universal statement. Tests are replays of previously evaluated v24 rules; follow-up inputs differ. No generalization to arbitrary rules or statistical significance is claimed.

Offline verification: `python -m unittest discover -s . -p test_api_v25.py -v` (14 passing tests). Responses in these tests are explicit mocks; no real API or student generations were performed locally.
